# ADR-0001 技术栈：Spring Boot 3.3 + JDK 17 + MyBatis-Plus

- 状态：已采纳
- 日期：2026-10-30
- 相关：`pom.xml`、`cs-bot/pom.xml`、`docs/roadmap.md` P1

## 背景

这套系统跑在一条弱网链路上开发（公网 2 Mbps、RTT 40–80ms），数据访问的每一次往返都是可见的成本。
同时这是个人长期项目，需要「三个月后还能改」。

## 决策

1. **Spring Boot 3.3.5 + JDK 17**（不用 21）。理由：17 是 LTS，本地已有；21 的 `switch` 模式匹配虽好，但会诱导 preview 参数。真要用，等 Spring Boot 基线抬到 21 再统一。
2. **MyBatis-Plus 3.5.7，不用 JPA。** 理由：本项目最贵的资源是往返次数和 SQL 形状。JPA 的隐式 N+1 与惰性加载在弱网上是灾难；MyBatis 让我直接写「一条 SQL 取全部所需」。
3. **Nacos 只做配置中心**，不做服务发现、不做路由事实源。单机部署不需要注册中心。
4. **不引 Lombok。** JDK 17 的 record 已覆盖大部分场景；少一个注解处理器少一层隐性行为（编译期改写 vs 运行期语义）。
5. **`cs-core` 零运行时依赖**，Spring 只出现在 `cs-bot` 适配层。

## 后果

- 好：SQL 可控、可解释、可优化；内核可脱离 Spring 单测（当前 13 个内核测试跑 0.1s）。
- 坏：需要手写大量映射；没有 JPA 的自动 DDL（用 Flyway 迁移，见 ADR-0004 的相关约定）。
- 约束：任何「用注解自动解决」的诱惑（自动分页、自动关联）都要先问「它会不会多一次往返」。
